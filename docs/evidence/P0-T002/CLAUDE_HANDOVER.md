### 3.4 Manifest scheme (why this document does not, and cannot, contain its own hash)

A file cannot contain its own final SHA256 - writing the hash into the file changes the file's bytes, which changes its hash, without end. Strict *mutual* embedding (this file containing JSON's final hash, and JSON containing this file's final hash) is equally impossible for the same reason: finalizing either file requires the other's already-final hash, so neither can be finalized first.

The scheme actually used is **sequential, not mutual**, per the brief's own allowance for "another clearly non-recursive cross-manifest arrangement", and it is re-applied identically every correction round (round 1 was the first application; rounds 2, 3, 4, 5, 6, 7, 8, 8B, the Step-21c final handover reconciliation, and the Step-21d final handover reconciliation were the 1st through 10th re-applications; this Step-21e final handover reconciliation is the eleventh re-application; the ordering rule itself has not changed since round 1):

1. `CLAUDE_HANDOVER.json` was finalized **first**. It lists SHA256 + byte size for all 24 non-evidence implementation files and does not reference either handover file's own hash - so it depends on nothing not yet known, and can be finalized without circularity.
2. JSON's own SHA256 was computed once finalized: `507984fa7ca3bdc787ae28673760b7a6e524418e588be48f941fd50440a43277` (134015 bytes) - recorded in section 3.3 above.
3. This Markdown file was finalized **second**, safely citing JSON's now-frozen hash (row above).
4. This file's own SHA256 is computed only after this edit is complete, so it cannot be written into this file, and it is deliberately **not** written back into JSON either - doing so would require re-finalizing JSON, changing the very hash this file just cited, reintroducing the circularity. ## 6. Design decisions carried into the implementation

- **Cut qualification (AA-C03):** `BRepAlgoAPI_Common(host, tool)` is built first; if `HasErrors()`, `KernelOperationFailed`. Otherwise the common shape's solid content is measured (`BRepGProp::VolumeProperties`); if there is no solid content, or the common volume is at or below `volume_epsilon = linear_tolerance^3`, the result is `NoIntersection` (never disguised as a kernel failure). Only once a qualifying positive common volume is confirmed does the adapter attempt the actual `BRepAlgoAPI_Cut`. This keeps the qualification and the real Boolean operation on the same API family (`BRepAlgoAPI_Common`/`BRepAlgoAPI_Cut`), but the Cut/Fuse decision paths never share code with the Fuse qualification below.
- **Fuse qualification (AA-C04):** deliberately NOT common volume. `BRepExtrema_DistShapeShape(a, b)` measures minimum separation; `separation > linear_tolerance` yields `NoIntersection`, otherwise `BRepAlgoAPI_Fuse` is attempted. This is what lets exact coplanar-face contact (corpus J04, zero separation, zero common volume) reach Fuse and succeed, while a small real gap (J05, 0.001) remains `NoIntersection` at every mandatory linear tolerance candidate (largest candidate 1.0e-4). `Fuse`'s successful path additionally requires exactly one resulting 3D solid (`ValidateAndWrapSolid(..., require_single_solid=true)`), per AA-C04 point 4.
- **Rectangle orthogonality (AA-C02):** `u_axis`/`v_axis` are converted to normalized `gp_Dir` values and tested with `gp_Dir::IsNormal(other, angular_tolerance)` - the caller-supplied angular tolerance, never a hard-coded value. A skewed-but-finite axis pair is classified `DegenerateGeometry` and is never silently rotated, projected, or corrected.
- **Boolean-family failure gate:** `HasErrors()` (from `BOPAlgo_Options`, the common base of `BRepAlgoAPI_Common`/`Cut`/`Fuse`) is used throughout, never `IsDone()` on that family - `IsDone()` on `BRepAlgoAPI_BuilderAlgo` itself was not independently verified during the OCCT API gate round, whereas `HasErrors()` was.
- **Exception containment:** every adapter entry point funnels OCCT work through `ContainOcctExceptions()` (`MakeLinearExtrusion`, `Cut`, `Fuse`) or an equivalent local try/catch (`Inspect`, `CaptureHistory`), each catching `Standard_Failure`, then `std::exception`, then `...`, translating all three to `KernelOperationFailed` (or, for `CaptureHistory`, the equivalent `GeometryError`). No third-party exception type is ever declared to cross the `geometry_api` boundary.
- **Result validation (`ValidateAndWrapSolid`):** shared by `MakeLinearExtrusion`, `Cut`, and `Fuse`. Rejects a null shape, a shape with zero 3D solid content, a shape failing `BRepCheck_Analyzer::IsValid()`, and a non-finite or non-positive computed volume - each as `InvalidResult`. `require_single_solid` additionally enforces exactly one solid for `MakeLinearExtrusion`'s single-prism output and `Fuse`'s connected-union contract.
