## Observed fact

Claude (Implementation Engineer) has no command-execution tool available
for the approved Windows target machine in this session. Only file
list/stage/commit/access-request tools exist for interacting with the
Windows machine (via the remote-devices file bridge); there is no
equivalent to running a shell command on that machine.

## Evidence

Claude checked, via `ToolSearch`, for any command-execution capability
against the Windows target before raising the ACR, and found none — only
`get_device_info`, `device_list_dir`, `device_stage_files`,
`device_commit_files`, and `device_request_folder_access` (file-transfer
and listing tools). This was re-confirmed again later in this same session
(see `docs/project-control/TASK-LEDGER.md` row 3 and the equivalent check
performed before Phase C resumed).

## Affected locked decision / criterion

Implementation Brief section 6 (execution protocol) assumes Claude
performs Phase A preflight and subsequent phases directly on the target
machine. Without command-execution access, Claude cannot run `git`, `cmake`,
`ctest`, `vcpkg`, or any other native tool on that machine itself.

## Options considered

- **Option A:** Block the task entirely until Claude is given
  command-execution access to the Windows machine.
- **Option B:** Claude authors PowerShell runbooks/scripts with rigorous
  safety checks; a human Windows Execution Operator runs them; raw output
  and exit codes are returned and treated as authoritative; Claude never
  claims a result it has not seen real evidence for.

## Recommended option

Option B — it is Claude's stated recommendation and lets the task proceed
without blocking on an environment change outside this session's control.

## Work paused pending resolution

All repository bootstrap and Phase C implementation work was paused until
ACR-P0T001-001 was resolved.
